1. Aim

To design and develop a full-stack, database-backed web application using HTML, CSS and JavaScript on the client side and Node.js with Express and an SQLite database on the server side, communicating through a REST API that exchanges JSON.

2. Description

Colleges run many events every semester - hackathons, cultural nights, sports leagues, workshops and guest talks. Registrations are usually collected on paper or through scattered online forms, which makes it hard for students to see what is coming up and hard for organisers to know how many seats are left.

Campus EventHub brings all of this into one website. Students sign up, browse and search events, filter them by category and date, open an event to read the details, register with one click when seats are available and cancel if their plans change. A My Registrations page lists everything they have signed up for. The admin (event coordinator) logs in to an admin panel to create, edit and delete events, see overall statistics and view or download the list of students registered for each event.

All rules are enforced on the server - seat capacity, one registration per student per event, no registration for past events and admin-only actions - so the data stays consistent even if someone calls the API directly.

5. System Architecture

The application follows a three-tier client-server architecture. The browser loads static HTML, CSS and JavaScript from the Express server; the JavaScript then calls the REST API with fetch(). The server authenticates the request, applies the business rules and reads or writes the SQLite database, and sends back JSON that the page renders.

Request flow example - student registers for an event

  1. The student clicks Register now; event.js sends POST /api/events/1/register with the login cookie.
  2. loadUser verifies the JWT and sets req.user; requireAuth lets the request through.
  3. The route checks the event exists, is upcoming, is not full and the student is not already registered, then inserts a row in registrations.
  4. The server replies 201 Created with the updated event; the page shows a toast and redraws the seat bar.

9. How to Run

Requirement: Node.js 22.13 or newer (developed on Node.js 24). SQLite is built into Node, so nothing else needs to be installed.

git clone https://github.com/chhelu123/campus-eventhub.git
cd campus-eventhub
npm install
npm start          # then open http://localhost:3000
  • On the first run data/eventhub.db is created with the admin, 5 sample students, 8 events and sample registrations (event dates are relative to the first run).
  • Admin login: admin@eventhub.com / admin123. Delete the data/ folder to reset the database.
  • Optional environment variables: PORT, JWT_SECRET, DB_PATH.

11. Conclusion

Campus EventHub meets the goal of the mini project: it is a complete full-stack web application in which the browser (HTML, CSS, JavaScript) communicates with a Node.js / Express REST API that stores data in an SQLite database. Students can find and register for college events in a few clicks, and the admin can manage events and see registrations in real time.

Building it covered the core topics of web programming: semantic HTML forms, responsive CSS layouts with Flexbox and Grid, DOM manipulation and fetch() in JavaScript, HTTP methods and status codes, REST API design, server-side validation, relational database design with keys and constraints, and secure authentication with hashed passwords and cookies.

Future enhancements

  • Email confirmation and reminders for registrations
  • Event posters (image upload) and a waiting list when an event is full
  • QR-code tickets for marking attendance at the venue
  • Deployment to a cloud host with HTTPS and a custom domain
